# Maven Dependency Analyzer

CLI-приложение на чистом C++17 для анализа зависимостей пакетов Maven (Maven Central), построения графа зависимостей с помощью DFS, обнаружения циклов, фильтрации и визуализации.

## Требования

- Компилятор с поддержкой C++17 (g++, clang++)
- Операционная система: Windows / Linux / macOS
- Утилита curl (используется для получения pom.xml из реальных репозиториев без внешних сетевых библиотек)

---

## Архитектура проекта

Проект разделен на следующие основные модульные компоненты:

- config.hpp / config.cpp — парсинг и валидация конфигурационного файла (config.json).
- maven.hpp / maven.cpp — логика работы с Maven Central (поддержка test_mode и скачивание pom.xml через системный curl), а также XML-пайплайн для сбора прямых зависимостей (groupId, artifactId, version).
- graph.hpp / graph.cpp — построение графа зависимостей методом глубинного поиска (DFS), обработка циклов и фильтрация по подстроке.
- main.cpp — точка входа CLI-приложения.

## Этап 1: Конфигурация и структура проекта

На первом этапе была спроектирована модульная структура всего приложения, разделенная на логические компоненты для конфигурации, работы с репозиторием и графами. Реализован собственный легковесный парсер конфигурационного файла config.json, который считывает ключевые параметры запуска: имя целевого пакета, адрес репозитория, флаг тестового режима, версию пакета, путь к выходному файлу графика, параметр генерации ASCII-дерева и строку фильтрации. Также на этом этапе была настроена кроссплатформенная система автоматизации сборки и управления через скрипт run.bat, позволяющая быстро компилировать проект, запускать тесты и очищать временные файлы.

## Этап 2: Сбор данных и парсинг pom.xml

На втором этапе реализован механизм получения файлов описания зависимостей из Maven-репозиториев. Предусмотрен гибкий режим работы: в тестовом режиме (когда test_mode равен true) приложение считывает локальный файл конфигурации или заранее заготовленный test_pom.xml, а в боевом режиме выполняет интеграцию с удаленным официальным репозиторием Maven Central через системные вызовы curl, скачивая актуальные pom.xml файлы по стандартным путям. Для обработки полученных данных написан собственный XML-пайплайн на стандартной библиотеке C++ без применения тяжеловесных сторонних библиотек. Этот парсер последовательно находит блоки тегов зависимостей, извлекая из них groupId, artifactId и версию для дальнейшей обработки.

## Этап 3: Построение графа зависимостей (DFS)

На третьем этапе реализована логика построения полного графа зависимостей исследуемого пакета с использованием алгоритма обхода в глубину (DFS). Функция рекурсивно запрашивает прямые зависимости для каждого найденного узла. Чтобы избежать зависаний и бесконечных циклов, которые часто встречаются в реальных графах Maven, встроена надежная система детектирования циклов на основе отслеживания посещенных вершин и вершин, находящихся в текущем стеке обхода (visited и visiting множества). Дополнительно на этапе построения графа реализована фильтрация зависимостей на лету по заданной подстроке (filter_substring), что позволяет исключать из графа ненужные типы артефактов (например, тестовые зависимости).

## Этап 4: Вывод структуры (ASCII-дерево и визуализация)

На четвертом этапе реализована визуализация и текстовое представление полученного дерева и графа зависимостей. Приложение формирует структурированный список смежности для каждого узла графа, выводя связи между пакетами в удобном для чтения виде в консоль. Предусмотрена логика подготовки данных для генерации графических представлений структуры связей, опираясь на параметры конфигурационного файла, такие как отображение ASCII-дерева и сохранение результатов в графические файлы.

## Этап 5: Тестирование и финальная сборка

На пятом этапе выполнено комплексное тестирование всех компонентов приложения, включая проверку корректности чтения различных конфигурационных файлов, стабильность работы XML-парсера при обработке реальных файлов из Maven Central и корректность обхода графов с помощью алгоритма DFS. Создана отдельная тестовая инфраструктура (включающая тестовые модули), позволившая убедиться в отсутствии утечек памяти, корректной обработке ошибок сети и правильной фильтрации данных перед финальной демонстрацией работы программы.

## Инструкция по сборке и запуску

1. Сборка проекта:
   run.bat build

2. Запуск тестов:
   run.bat test

3. Запуск программы с конфигурационным файлом:
   run.bat config.json

4. Очистка скомпилированных файлов:
   run.bat clean
